### `windowfeatures` on links and forms skips window farbling, now web-reachable

M159 item "Declarative `windowfeatures` skips Brave's window farbling", which
needed the experimental flag.

- [ ] Wrap `GetWindowFeaturesFromAttribute(feature_string, dom_window)` through
      `MaybeFarbleWindowFeatures()` like `GetWindowFeaturesFromString()`
      (`dom_window` can be null)
- [ ] Or add `"WindowOpenSplitTab"` to `kBraveDisabledTrialNames` in
      `chromium_src/third_party/blink/common/origin_trials/origin_trials.cc`
      (depends on whether Brave wants web-initiated split tabs)
- [ ] Add a farbling browser test for `<a windowfeatures>`

### `brockit rebase` stops on a pinned group's fixup of a file a later squash adds

Brockit places a pinned group's `fixup` right after the group's first commit, so
a fixup of a file that a later `squash` of the group adds stops on a
modify/delete. cr160 (2026-11-13): `0483b64db43`
`fixup! [cr160] Version CodeHealth tracker` on
`tools/cr/codehealth/scripts/knowledge_base_test.py`, added by the group's third
`squash`; cr159 hit the same with `Version lift updates`. The fix, by hand each
time, was to keep HEAD's state and requeue the `fixup` line after the group's
last `squash`.

- [ ] Place a pinned group's fixup after the group's commit that last touches
      (or adds) the fixup's files, or after its last `squash`, when building the
      todo
